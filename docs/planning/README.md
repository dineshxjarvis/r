# Planning workbench

This directory contains temporary, living coordination documents used while production domains are being designed. They are not product requirements or architecture authority.

- [`v0.01-scope.md`](v0.01-scope.md) — first buildable backend milestone: domains in and out, feature-to-collection map, phase order and exit tests
- [`production-design-tracker.md`](production-design-tracker.md) — wave status, requirement coverage, conflicts, decisions and exit gates
- [`whole-system-gap-audit-prompt.md`](whole-system-gap-audit-prompt.md) — mandatory pre-design and adversarial post-design reasoning procedure
- [`cross-role-accountability-and-flow-audit.md`](cross-role-accountability-and-flow-audit.md) — adversarial audit of people, appointments, inspector classification, attendance accountability, handoffs and failure recovery
- [`role-model-gap-register.md`](role-model-gap-register.md) — separate active register for the 22 role, authority, scope, handoff and operability gaps
- [`role-and-scope-atlas.md`](role-and-scope-atlas.md) — visual, scalable catalogue of field populations, mine posts, multi-mine hierarchy, external authorities and bounded platform administration
- [`wave-11-grievance-gap-audit.md`](wave-11-grievance-gap-audit.md) — production grievance/protected-intake conflict and failure audit
- [`wave-12-integration-gap-audit.md`](wave-12-integration-gap-audit.md) — connector trust, delivery, mapping, reconciliation and recovery audit
- [`wave-13-analytics-ai-gap-audit.md`](wave-13-analytics-ai-gap-audit.md) — AI component, lineage, evaluation, human authority and lifecycle audit
- [`wave-14-experience-gap-audit.md`](wave-14-experience-gap-audit.md) — English/Hindi, accessibility, assistance and mobile-scope audit
- [`wave-15-production-hardening-gap-audit.md`](wave-15-production-hardening-gap-audit.md) — executable contracts, security, audit, reliability, recovery, migration and release audit

When planning finishes, durable decisions move to `docs/decisions/`, requirements to `docs/product/`, and domain rules to `docs/features/`. The tracker remains as provenance or is archived; it never silently becomes the canonical specification.
