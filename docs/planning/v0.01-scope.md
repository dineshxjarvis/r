# Strata — v0.01 Backend Scope

What the first buildable milestone covers, why those boundaries, and the order it gets built in. The contract itself is unchanged and unreduced — this document only says which slice of it v0.01 implements.

## 1. What v0.01 has to serve

**Web**

1. Role-based dashboard
2. GIS mine map
3. Compliance tracking
4. Inspection management
5. CAPA management
6. AI Risk Detection
7. CAPA Effectiveness Intelligence
8. Regulatory Change Impact Intelligence

**Mobile (Flutter + PowerSync, inspectors and field workers)**

9. Assigned inspection
10. Geo-tagged inspection
11. Photo + observation
12. Offline mode and sync

## 4. Deferred within the kept domains

Kept domains ship partially. Named here so the gap is deliberate rather than forgotten.

- **identity** — `contractor-organizations`, `contractor-engagements`, `record-parties`, `asset-responsibilities`, `authority-units`, `signing-identities`
- **documents** — `document-filings` (statutory filing belongs to `reporting`)
- **inspections** — `inspection-requests`, `inspection-responses`, `inspection-handovers`
- **workflow** — `approvals` (CAPA verification is already an action with its own separation-of-duty rule; a general approval object is not yet needed)
- **geospatial** — `spatial-sources`, `spatial-source-policies`, `spatial-imports`, `spatial-topologies`, `spatial-assertions`, `spatial-resolutions`, `spatial-derived-products`, `surface-models`, `spatial/health`. v0.01 seeds mine boundaries and geofences through a migration rather than an import pipeline
- **analytics** — `ai-dataset-versions`, `ai-feature-versions`, `ai-evaluation-runs`, `ai-drift-signals`, `ai-monitor-observations`, `ai-incidents`, `ai-label-assertions`, `ai-audit/runs`, `ai-deployments/{id}/monitoring`

The AI **governance chain** is not deferred, even at v0.01: `ai-use-case-versions` → `ai-model-versions` + `ai-prompt-template-versions` + `ai-provider-profiles` → `ai-deployments` → `ai-runs`. Without it an AI output cannot name its own provenance, which is the whole point of the analytics contract. What is deferred is drift monitoring and the evaluation harness.

## 5. How the three AI features work at v0.01

All three are L4. They emit `signal` records with lineage and never write an L2 fact.

**AI Risk Detection.** A versioned signal definition scores defects, findings and obligation instances on recurrence count, ageing band crossing, severity and overdue state — deterministic, evaluated against `defect_ageing_band_config`. The LLM writes the explanation, not the score. Output is a `signal` carrying its `signal_definition_version_id` and the record references behind it.

**CAPA Effectiveness Intelligence.** A versioned metric over CAPAs that reached `VERIFIED_CLOSED`: did a finding recur on the same defect within the window. Fully deterministic. Emits a signal when a closed CAPA turns out not to have worked. Depends on nothing but the defects domain and time.

**Regulatory Change Impact Intelligence.** New document version → OCR → `extraction` → diff against published `obligations` → `obligation-conflicts` → impacted `obligation-instances` resolved per mine through applicability rules → `signal`. This is the one with real generative AI in the path, and every proposal carries the document and segment hashes it was grounded in. A proposal is never a published obligation until a human accepts it.

## 6. Build order

Each phase ends with its authorization boundary tests green, not just unit tests.

| Phase | Content | Exit test |
|---|---|---|
| **P0** | Kernel: four route forms and three companions, envelopes, query compiler, idempotency, version/ETag, `as_of`, introspection. Audit hash chain and transactional outbox. RLS session wiring. OpenFGA client with fail-closed behaviour | All seven route forms work end to end on one toy resource; a forced OpenFGA outage denies rather than allows |
| **P1** | `identity`. Tenants, organizations, units, people, principals, affiliations, mines, subunits, assets, posts, position templates and capability policies, appointments, mandates, jurisdictions, responsibility routes, sessions. FGA projector with conditional tuples | The same `Check()` allows before appointment expiry and denies after, with no job run in between |
| **P2** | `documents`. Blobs, segments, extractions, obligations, applicability rules, obligation instances, conflicts | An obligation instance is generated for the right mines from an applicability rule; an unresolved applicability is visible, not silently absent |
| **P3** | `inspections`, `evidence`, `observations`. Assignment, offline capture, sync | A capture made offline syncs after reconnect, the device hash chain verifies, and a replayed sync is a no-op rather than a duplicate row |
| **P4** | `defects`, `findings`, `capas`. Closure gate | Closure evidence captured away from the target produces an explainable `DISTANCE_MISMATCH` and blocks the close |
| **P5** | `geospatial`, `dashboard`. Governed geometry versions, map compositions, projections, metric manifests | A dashboard metric drills down to the exact records; projection lag is visible and an error never renders as zero |
| **P6** | `analytics`. The three signals and the governance chain | Every AI output names its use case, model, prompt template and provider versions, and the input hashes it was grounded in |

## 7. Blockers carried in from the docs

Three things must be settled before or during P0, because they are contradictions in the specification rather than open design questions.

1. **ID scheme.** `../api-specs/README.md` says UUIDv7 is native; `../architecture/data-model.md §0` says `<prefix>_<ULID>` as `TEXT PRIMARY KEY`, and `evidence.md` requires client-generated ULIDs for offline capture. **Resolved: ULID as TEXT.** The one paragraph in `api-specs/README.md` needs correcting.
2. **Foundation remap.** `data-model.md`'s own preamble states that §1 is superseded by `identity-authority-model.md` and `foundation-data-model.md`, and that §2–§6 must be remapped to the corrected foundation before implementation. That remap is a prerequisite for P1's migrations, and it is the largest unscheduled piece of work in this milestone.
3. **Audit and outbox placement.** `data-model.md §3.7` proposes building the audit trail and outbox as one pass after Domain 5. This scope rejects that: they are the transaction boundary every service commits through, so they land in P0. Retrofitting them later means rewriting every handler written before the retrofit.

## 8. Explicitly not claimed at v0.01

- Storage is not immutable at rest. Supabase Storage has no Object Lock; immutability is enforced by insert-only credentials and content addressing. Production needs real S3 with Object Lock in compliance mode.
- No external authority integration. Regulatory data is seeded and mock.
- No signing. Statutory submission and DSC/eSign belong to `reporting`, which is out of scope.
- No drift monitoring or AI evaluation harness.
- Single environment, no HA, no measured SLO, RPO or RTO profile.

The full production gate list stays owned by `../features/platform/production-hardening-spec.md`.
